# Adaptive Detail 1.0.0

License: [MIT](../../licenses/Adaptive_Detail.txt). ReShade and AMD validation
notices are retained in `THIRD_PARTY_NOTICES.md`.

A restrained, luminance-driven ReShade sharpener for softened game images. Two distinct spatial bands share one correction budget. Supports sRGB SDR, full-range PQ/BT.2020, and signed/extended linear scRGB.

**Default behavior is safe bypass.** Select an input/output contract only after verifying the actual sampled COLOR resource and destination. The shader cannot establish that contract from Windows HDR, bit depth, FP16, or presentation metadata.

## Install and start

1. Copy both files from `Shaders/` into a directory in ReShade's Effect Search Paths, usually `reshade-shaders/Shaders/`.
2. Reload effects, then enable **Adaptive Detail**. It initially bypasses.
3. Read `INSTALL_AND_CONTRACT.md`. Once the encoding is verified, select the matching contract in the effect UI.
4. Begin with **Natural Detail**, or load the corresponding `.ini` from `Presets/`. There are three artistic presets, each supplied for SDR sRGB, HDR PQ and HDR scRGB. Selecting an explicit preset asserts its named contract; it is not an encoding detector. These standalone presets enable only Adaptive Detail; copy their values manually if retaining an existing effect suite.
5. Disable other sharpening initially, including ReShade CAS/LumaSharpen, game sharpening sliders and driver sharpening, where available. Tune while moving the camera as well as while paused.

No external shader pack, texture asset or native add-on is required. The implementation targets modern graphics APIs with full-resolution R32F render targets. HLSL SM5 and GLSL were generated by the actual ReShade FX frontend; GPU driver compilation and game integration remain untested.

## Tuning

Start with Master 0.65, Fine 0.45, Detail 0.10. Increase **Fine** only until softened texture becomes readable. Then reduce it slightly. For a modest surface-detail emphasis, increase **Detail** instead of increasing both controls. Its support is fixed at two output pixels.

If edges acquire rims, increase **Edge / halo protection** or lower Master. At maximum edge protection, sharpening cannot expand local luminance extrema; real peaks also receive less enhancement. If grain, hair or foliage becomes restless, increase **Noise protection**, then lower Fine/Master. This is a spatial heuristic; it cannot recognize skin, foliage or UI.

Use the split view for still comparisons, then return to normal view and test slow pans. Stacked sharpening is nonlinear: the first filter changes the edges, noise and extrema seen by the next. Reintroduce any preferred game/upscaler sharpening one control at a time and retune this effect. When a sharpening stage cannot be disabled, use lower strengths here.

## Presets

| Preset | Master | Fine | Detail | Edge | Noise |
|---|---:|---:|---:|---:|---:|
| Natural Detail | 0.65 | 0.45 | 0.10 | 0.85 | 0.80 |
| TAA Softness | 0.85 | 0.80 | 0.10 | 0.80 | 0.75 |
| Texture Focus | 0.65 | 0.35 | 0.35 | 0.90 | 0.85 |

The three encoding variants share artistic values; only their contract selection differs. Controls are dimensionless. SDR uses relative linear RGB, while HDR analysis uses linear component nits divided by 80. Consequently the small absolute shadow/noise regularizers correspond to different fractions of the scene's diffuse white when HDR content uses a higher diffuse-white level. No monitor calibration or peak-luminance value is assumed.

## Quality and features

Set preprocessor definitions in ReShade, then reload:

```ini
ADAPTIVE_DETAIL_QUALITY=1
ADAPTIVE_DETAIL_ENABLE_DETAIL=1
ADAPTIVE_DETAIL_VERIFIED_CONTRACT=0
```

- **0 — Normal:** point-sampled fine analysis plus paired bilinear evaluation of the detail kernel.
- **1 — High, default:** point-sampled evaluation throughout; avoids texture interpolation-weight approximations.
- **2 — Ultra:** deliberately aliases High. There is no demonstrated reason to add more samples to this finite kernel.
- Set `ADAPTIVE_DETAIL_ENABLE_DETAIL=0` to remove the detail control, broad-kernel samples and detail-only bilinear sampler. Both passes and the shared R32F texture remain necessary for fine sharpening.

Quality never changes the intended radius or artistic strength. High's measured advantage over Normal is numerical, very small in the tested scenes; no visible-quality or performance superiority is claimed. Normal is a sensible lower-fetch alternative. Presets do not change quality definitions.

## Optional other effects

HDR IPS Enhance and HDR Bloom are also included. Their source contracts overlap
for verified PQ/BT.2020 and scRGB/BT.709 while remaining distinct operations.
A source-based starting order is **HDR IPS Enhance → Adaptive Detail → HDR
Bloom**: establish contrast, sharpen texture, then add diffusion. This is a
suggestion, not a tested compatibility recommendation. Adaptive Detail can
also process verified SDR sRGB; HDR IPS Enhance is bypass-only for SDR. Reduce
overlapping sharpening controls, and verify the sampled/destination contract
again if any effect changes encoding or injection location.

## What is and is not verified

See `VALIDATION.md` and the retained package reports under
`../../validation/Adaptive_Detail/results/`. These are historical results from
the supplied Adaptive Detail 1.0.0 package. New repository integration checks
are recorded separately in
[`validation/RELEASE_VALIDATION.md`](../../validation/RELEASE_VALIDATION.md).
The original tests and their provenance remain in the repository. No GPU
timing, FPS, game screenshots or in-game validation is claimed.

This filter cannot reconstruct missing information, remove temporal ghosting, increase rendering resolution, lower the monitor's physical black level or provide local dimming. It does not tone-map, change exposure, add saturation, bloom or deband. It also cannot guarantee zero average-luminance bias on every image: asymmetric local adaptation can produce small changes.
