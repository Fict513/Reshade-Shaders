# Independent audit — version 1.0.1

The attached 1.0.0 source was treated as unverified. Three reproducible defects justified changes. Artistic controls, curves, filter design, matrices, quality definitions and all three presets are retained.

| Finding | Evidence | Change |
|---|---|---|
| Float32 PQ evaluation loses precision | Executing extracted production functions on 65,536 highlight samples from 80–1000 nits produced three downward one-code steps after actual 10-bit PQ rounding. The predominantly double NumPy test had reported none. | Algebraically equivalent ST 2084 evaluation avoids cancellation in the decoder denominator and division of nearly equal large terms in the encoder. Same transfer function and absolute units; no new tone mapping. Revised production-body CPU test has zero reversals in these ramps. |
| Finite scRGB input can overflow processing | Finite RGB=(1e38,1e38,1e38) produced NaNs when multiplied by 80. This is an FP32 robustness case, far beyond normal HDR content and the finite FP16 storage range. | Return the original sample if decoding, luminance, processed RGB or output conversion becomes nonfinite. The guide uses its existing low-luminance fallback for nonfinite Y. Finite signed scRGB remains unclamped. |
| Claimed resolution validation did not change resolution | The FX harness inserted 3440×1440 before supplied definitions. ReShade's preprocessor keeps the first macro definition. Consequently the seven supposed resolution configurations all retained the defaults. | Supplied dimensions now precede defaults; validation requires the actual compiled texture dimensions in module metadata. All seven distinct resolutions now pass. |

Added seven CPU tests using extracted production function bodies. They cover Main, matrix/color math, diagnostics, exact return paths and a separate local-filter adapter. They complement the existing reference tests; they are not an FX interpreter or GPU execution. The baseline regression result records the original ZIP SHA-256.

## Independent reasoning and trace

1. COLOR is fetched through the non-sRGB view at integer pixel coordinates. Both passes disable sRGB writes and blending. The preparation pass writes only its R32F guide; the final pass writes the caller's target. The source copy remains the same input for both passes in the intended final-buffer path. Host resource format conversion and downstream Windows/display processing remain outside this effect.
2. PQ decodes each BT.2020 component to absolute component nits. scRGB multiplies signed linear BT.709 by 80 and changes primaries to BT.2020. Defined Y is dot(RGB, (0.2627,0.6780,0.0593)). Nonpositive Y bypasses; it is not forced to black. Neither bit depth nor FP16 identifies an encoding.
3. The global stage returns target Y. The local stage multiplies that target by a bounded power of two derived from original log Y. RGB scales by target/source Y, subject only to incremental PQ-domain headroom. There is no monitor-peak mapper. The color stage adds constant-Y chroma within its incremental budget. Master blends in linear light; the inverse matrix/scale or PQ inverse EOTF restores the original contract.
4. For lower log segment t, the global log derivative is 1-c(2t-3t²); for upper t it is 1+c(1-4t+3t²). Both are at least 1-c/3 ≥ 5/6 over supported controls. Endpoint displacements are zero; derivatives are 1 at toe/high end and 1+c on both sides of the anchor. The curve is C1 and strictly increasing in real arithmetic. Linear-light master blending with identity retains increasing luminance for this global-only scalar curve. This proof does not imply a spatially varying local stage is globally order-preserving.
5. The bilateral filter weights are nonnegative, include the center, and share the same spatial/range scales across tiers. Corrections are bounded by strength/2 stops before protection and then constrained by sampled extrema. Borders clamp. Sparse rounded samples are not a dense bilateral convolution; thin-edge and low-contrast halo risks remain. The filter is not mean preserving, and global contrast can also change scene-average luminance. No universal brightness-conservation claim is justified.
6. Color expansion preserves the defined linear Y and chromatic direction around neutral in real arithmetic. It does not preserve perceptual hue exactly. A signed ICtCp extension would add domain and inverse-transform choices; no demonstrated improvement justified replacing the existing restrained operation. P3-D65 is an enhancement proxy, not the measured panel gamut. Out-of-proxy source colors receive no additional chroma; global/local luminance gain may still affect them. Gray, dark and highlight gates plus incremental budgets are retained.
7. Master zero, unsupported/unknown contract, invalid input, and fully neutral normal output return the original sampled float4 directly. Every diagnostic also returns original alpha. These are sampled-signal guarantees, not a claim of identical physical output bits after host target conversion.
8. False color measures pre-effect source Y. Signed correction measures post-master Y change. Activity red/green show removed incremental gain/chroma; blue is only the highlight-protection envelope. Palettes are linear BT.709 component-nit colors, converted to active output encoding. They do not measure the monitor.

## Primary-source verification

The README links ITU, Microsoft and official ReShade sources. Rechecked the following independently:

- [Microsoft Advanced Color](https://learn.microsoft.com/en-us/windows/win32/direct3darticles/high-dynamic-range): linear BT.709 scRGB nominal 80 nits per unit; signed extended components; format and color-space signaling are separate. Destination must retain the established contract.
- [ITU-R BT.2100-3](https://www.itu.int/rec/R-REC-BT.2100-3-202502-I/en), Table 4: PQ constants and absolute 10000-nit normalization. The rewritten expressions are algebraically identical: c2-c3=1-c1=0.1640625. The inverse-EOTF ratio is 1-(1-c1)(1-p)/(1+c3*p).
- [ReShade FX reference](https://github.com/crosire/reshade-shaders/blob/slim/REFERENCE.md) and [runtime](https://github.com/crosire/reshade/blob/7bf9de8b33bcc76c3177007e65d73c72dd0f34c0/source/runtime.cpp): COLOR binding, SRV selection, matching copy format, presentation macro and unknown non-backbuffer permutations. Auto remains opt-in after contract verification. No native add-on is necessary for the ordinary final-buffer path.
- [ReShade preprocessor](https://github.com/crosire/reshade/blob/7bf9de8b33bcc76c3177007e65d73c72dd0f34c0/source/effect_preprocessor.cpp), add_macro_definition: nonidentical macro redefinition fails and retains the earlier definition, confirming the harness defect.

No game's actual injection point, resource view or output target was available for capture. Follow README contract verification before enabling this effect; automatic presentation metadata alone cannot validate an intermediate buffer.
